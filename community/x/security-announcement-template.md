# Security announcement template

Templates for security-relevant posts on X. Placeholders in {braces}. These
posts preempt the regular cadence, temporarily replace the pinned post while
active, and always mirror a notice on noendstate.com — the site leads.

---

## Scam warning (fake accounts, fake mints, phishing)

```
Security notice: {what is circulating — e.g. "a fake account impersonating us is DMing mint links"}.

Facts: we have no mint. No contract exists. We never DM first.

The only official sources are noendstate.com and the channels it lists. {specific fake identifier if known, e.g. the fake handle} is not us.
```

Follow-up reply if members may have interacted:

```
If you clicked or signed anything from {fake source}: assume compromise. Move assets from a clean device now. We cannot recover funds. Details and updates: {site url}
```

---

## Official-surface change (new channel, new link, future contract publication)

Posted BEFORE or simultaneously with the change, never after rumors.

```
Official change: {what is being added or changed — e.g. "our Telegram channel is now live"}.

The new official {surface}: {url}

Verify it at noendstate.com — anything not listed there remains fake. Nothing else about our official surfaces has changed.
```

For any future contract address publication (none exists today), the same
shape applies with one addition:

```
Contract published: {label} on {chain}.

The address is on noendstate.com and official channels simultaneously — read it only from there. We will never post an address anywhere else first, and never in a reply or DM.
```

---

## Compromised account or bot

```
Security notice: {which account/bot} was compromised at approximately {time, UTC}.

Disregard everything it posted after that time. Links and addresses it shared are void.

Status and instructions: noendstate.com — treat the site as the only source until we post the all-clear here.
```

All-clear:

```
Resolved: {account/bot} is back under our control as of {time, UTC}. Malicious posts are removed and documented.

What happened and what changed: {postmortem/chronicle url}
```

---

## Rules

- Speed first: the first notice goes out with what is known, and says what
  is not yet known. Corrections append in replies, never by deleting.
- Every notice names noendstate.com as the root of trust.
- Pin the active notice; restore the standing pin when resolved.
- Every security notice becomes a Chronicle entry ({NES-NNNN}) once facts
  are stable; the resolution post links it.
- Never speculate about attacker identity in public.
